Smaller known gaps. Defects found in firmware review now live in SECURITY.md
("Known issues") so anyone deploying this sees them; this file is the working
list of things to build.

- mass jam of rf alert — detect that the receiver has gone deaf
- battery low on the device itself

- the device decodes its OWN siren transmissions as sensor events. Unpaired
  families 0x3F010 and 0x62237 appear in /events with multiple nibbles, and
  0x622374 is this device's own siren EV1527 address from the siren work. The
  CC1101 is almost certainly hearing its own TX. Must be investigated BEFORE
  anyone pairs either id — pairing a self-transmission would make the device
  alarm on its own siren. Found during the sensor-families audit; that work
  neither fixes nor depends on it.
- register the Telegram webhook so bot commands work
- move telegramBotToken/telegramChatId into projects/{id}/secrets/notify, the
  way the Pushover credentials already are. They are on the member-readable
  project doc today (see SECURITY.md). Needs a backfill that writes the
  secret, flips every read to the new path, then clears the old fields.
- Pushover image attachments, so a breach photo reaches a Pushover-only
  project. onSnapshotUploaded currently sends the photo via Telegram and only
  the caption text through notify().
- deep-link an alert to the SPECIFIC event. The Pushover notification already
  links to /explore, but ExplorePage reads no query parameter, so the link
  lands on the unfiltered list. Teaching it to honour ?rfId=&ts= and
  pre-select that row would put the triggering sensor's snapshots on screen
  directly from the notification. notify() would take the rfId and build the
  query; APP_EVENTS_URL is the seam.
- test + deploy the watchdog / offline-alert work (docs/testing-device-liveness.md)

- multi-siren support. The siren base address is a SINGLE value end to end:
  Firestore projects/{id}.sirenBaseAddress (string), RTDB config `s` (number),
  Config::sirenBaseAddress, and RelaySiren drives one address. Supporting a
  second siren means making all four a list — the `m` (remotes) plumbing is
  the model to copy. Note Config gaining a field changes sizeof(Config), so
  it needs an EepromStore::kMagic bump, which discards stored config on the
  first boot after flashing; the siren address itself now survives that,
  because it is re-adopted from the cloud.
