
BLOCKED ON HARDWARE (ESP32 ordered 2026-08-20)
  A. Cloud EVENT WRITES don't work on the ESP8266 — heap fragmentation.
     Mint, RTDB auth and /config + /commands polling all work; only
     reportEvent()'s TLS write is disabled (kMinBlockForEventWrite floor),
     because attempting it below ~5KB contiguous RESETS the board rather
     than failing cleanly. After the first TLS cycle the largest free block
     settles at ~3.4KB and never recovers, though ~10KB stays free.
     Consequence today: no Firestore timeline entries and no Telegram
     alerts for real sensor triggers. Local alarm logic, siren, EEPROM
     state and LAN arm/disarm are unaffected.
     Full measurements + what was already tried: cloud_client.cpp top note.
     Options: ESP32 migration (planned), or route events through the
     plain-HTTP deviceIngest function instead of a direct TLS RTDB write.
  B. Verify remote arm/disarm end to end. Polling delivers /commands
     (verified: commands.armed -> true reached the device), but the full
     round trip from the web UI hasn't been watched through to the siren.
  C. CC1101 not wired — RF decode untested against real Kerui packets;
     battery bit position in the 24-bit packet still unconfirmed.
  D. No siren wired — RelaySiren untested end to end.
