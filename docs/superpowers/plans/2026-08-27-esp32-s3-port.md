# ESP32-S3 Port — Implementation Plan

Created 2026-08-27. Unblocks "Next step 1" in CLAUDE.md: cloud event writes,
blocked on ESP8266 by heap fragmentation.

## Hardware (probed, not assumed)

`esptool.py chip_id` / `flash_id` on `/dev/cu.usbmodem1101`:

- **ESP32-S3 (QFN56) rev v0.2**, MAC `68:ee:8f:5b:82:dc`
- **8MB embedded PSRAM** (AP_3v3), **16MB flash**, 40MHz crystal
- **USB-Serial/JTAG** (native USB — not a CH340; none of the D1 Mini's
  115200-upload / 1s-EN-pulse workarounds apply)

Toolchain already on this machine: `platform-espressif32` 7.0.1,
`framework-arduinoespressif32` 3.20017 (Arduino core 3.x / ESP-IDF 5.x),
`toolchain-xtensa-esp32`. `FirebaseClient` 2.2.13 lists `espressif32` as a
supported platform.

## Why this port erases the blocker

The ESP8266 constraints were all consequences of ~40KB usable RAM and a 4KB
cont stack. On the S3 (~320KB internal SRAM + 8MB PSRAM, 8KB+ main task
stack, no cont stack) these stop being constraints:

| ESP8266 workaround | Fate on S3 |
|---|---|
| 2 TLS clients max (4 cost 11.8KB → OOM) | Restore 4 clients + SSE |
| `kMinBlockForEventWrite` floor disabling event writes | Delete the floor |
| 15s poll cadence as a heap budget | Replaced by SSE push |
| `noinline` on main.cpp helpers (cont-stack) | Harmless; keep, ESP8266-only |
| `-DPIO_FRAMEWORK_ARDUINO_MMU_CACHE16_IRAM48` | ESP8266-only flag, drop |

**Do not delete the ESP8266 evidence comments.** They stay behind `#ifdef`
or as-is; they document measured facts and cost days to establish.

## Approach: multi-env, one codebase

Add `[env:esp32s3]` beside `[env:d1_mini]` in the existing
`firmware/edge/device/platformio.ini`. Platform differences go behind
`#if defined(ARDUINO_ARCH_ESP32)` in a new `platform_compat.h`, so the
D1 Mini stays buildable as a fallback and the native test env is untouched.

## Known compile breaks (verified by reading the ESP32 headers, not guessed)

1. `eeprom_store.cpp:73` — ESP32's `EEPROM.h` has `getDataPtr()` but **no
   `getConstDataPtr()`**.
2. `cloud_client.cpp` (3 sites: ~175, ~314, ~477) — ESP32's
   `WiFiClientSecure` has `setInsecure()` but **no `setBufferSizes()`**
   (mbedTLS, not BearSSL; the tuning is unnecessary there).
3. Headers: `ESP8266WiFi.h`→`WiFi.h`, `ESP8266mDNS.h`→`ESPmDNS.h`,
   `ESP8266WebServer.h`→`WebServer.h`, class `ESP8266WebServer`→`WebServer`.
4. `ESP.getMaxFreeBlockSize()` → `ESP.getMaxAllocHeap()`; `ESP.wdtFeed()`
   has no ESP32 equivalent (task WDT is fed by yielding) — compile out.
5. `cont_t`/`g_pcont` stack probe in `cloud_client.cpp` — ESP8266-only.

## Tasks

### Task 1 — `platform_compat.h` + `[env:esp32s3]`, build only

Create `src/platform_compat.h` centralizing the header and API differences
(WiFi/mDNS/WebServer includes, a `WebServerClass` alias, `maxAllocHeap()`,
`feedWatchdog()`, `eepromConstDataPtr()`). Add the env:

```ini
[env:esp32s3]
platform = espressif32
board = esp32-s3-devkitc-1
framework = arduino
monitor_speed = 115200
board_build.flash_mode = qio
board_upload.flash_size = 16MB
build_flags =
    -DBOARD_HAS_PSRAM
    ${common.firebase_web_api_key_flag}
lib_deps = (same as d1_mini)
```

Then convert the call sites in `main.cpp`, `local_web_server.h/.cpp`,
`provisioning_portal.h/.cpp`, `eeprom_store.cpp`, `cloud_client.cpp`.

**Verify:** `pio run -e esp32s3` compiles clean AND `pio run -e d1_mini`
still compiles clean AND `pio test -e native` still passes 20/20.

### Task 2 — Pin map for the S3

The D1 Mini map (CS 15 / GDO0 4 / relay 5 / portal 0) is not valid on an S3:
GPIO15 is a strapping-adjacent pin and the S3's default SPI pins differ.
Choose safe S3 GPIOs (avoiding 0, 3, 45, 46 strapping pins and 26–32 which
are tied to the S3's SPI flash/PSRAM — **critical with 8MB PSRAM onboard**),
put them behind the same `#ifdef`, and document the intended wiring.

Boot-strap pin note: `kForcePortalPin = 0` works on the S3 (BOOT button) but
must be read after boot only.

**Verify:** compiles; on-device `pinMode`/`digitalRead` of the portal pin
behaves (BOOT button reads LOW when held).

### Task 3 — First flash + bring-up on real hardware

Flash over native USB (no `upload_speed` workaround needed):

```bash
cd firmware/edge/device && pio run -e esp32s3 -t upload --upload-port /dev/cu.usbmodem1101
```

Re-provision WiFi through the setup portal (LittleFS is empty on the new
board). Confirm: boot, WiFi connect, mint succeeds, `app.ready() -> true`,
`/config` polls through, LAN web server + mDNS reachable.

**Verify:** serial capture showing mint success and a config poll; `curl`
against the device's IP returns the local web UI.

### Task 4 — Restore event writes (the actual point of this port)

Delete `kMinBlockForEventWrite` and `kMinBlockForWrite` gating from
`reportEvent()`/`openDataClient()` for ESP32. Keep the `database_.set()`
return-value check (the silent-failure bug). Log free heap around the write
for one run to confirm headroom is a non-issue.

**Verify:** trigger a sensor event via the local web simulator → RTDB node
appears under `/{projectId}/events/{rfId}/{ts}` → Firestore timeline entry
appears in the web UI → Telegram alert fires. This is the end-to-end loop
that has never worked.

### Task 5 — Restore 4 TLS clients + SSE streaming

Replace the alternating 15s poll with the original design: separate clients
for auth, write, commands stream, config stream. Remove `kPollIntervalMs`
and the last-seen-value dedupe that only existed to suppress poll repeats.

**Verify:** remote arm/disarm from the web UI reaches the device in <2s
(vs up to ~30s). Soak 10+ min with no reset; heap stable across stream
reconnects.

### Task 6 — Docs + memory update

Update CLAUDE.md (hardware table, status, next steps) and the three memory
files, which currently assert ESP8266 limits as current truth. Mark them as
historical/ESP8266-specific rather than deleting — the ESP8266 fallback env
still exists.

## Sequencing note

Tasks 1–4 deliver the blocked functionality. Task 5 is a latency/architecture
improvement that is safe to defer if hardware time is short. CC1101 wiring
and the siren relay (CLAUDE.md next steps 2–3) remain independent and are
out of scope here.
